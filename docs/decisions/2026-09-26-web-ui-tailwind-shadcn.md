# Web app interface on Tailwind CSS and shadcn/ui

Date: 2026-09-26. Status: accepted.

## Context

The first Next.js release ported the single-page PWA as it was: one stylesheet written by hand, a phone layout stretched to any width, and controls without hover, focus or pointer feedback. On a PC the chat list and the conversation took the whole window in turn, and the pages for settings and users were a single card of stacked buttons.

## Decision

The interface is rebuilt on Tailwind CSS 4 and shadcn/ui (Radix primitives, copied into `webapp/src/components/ui`), with Lucide icons, Geist from the `geist` package, `next-themes` and `sonner`.

- From 768 px wide: the chat or activity list on the left and the open conversation on the right. Below: one view at a time and a tab bar at the bottom.
- Every control shows hover, focus and pressed states and the pointer cursor; icon buttons carry a label and a tooltip.
- Message actions: a toolbar on hover with a mouse, a sheet from the bottom on touch screens.
- Light and dark themes from the same tokens (`src/app/globals.css`), text pairs at 4.5:1 or more; the theme follows the system or the choice made in Settings.
- Confirmations, forms and menus use dialogs, fields with labels and inline errors, and dropdown menus instead of `confirm()` and `prompt()`.

## Consequences

- The components of `src/components/ui` are project code generated by the shadcn CLI (`components.json`); they are updated with `npx shadcn add`, not through npm.
- The fonts ship with the image: the build downloads nothing beyond npm packages.
